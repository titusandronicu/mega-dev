# Lessons learned
1. When a server says "don't guess", find the stated spec first (here: the attachment link hidden behind `#attachment-unavailable`).
2. Count limits with a tool. Show every cut to the human.
3. A form field can ask for something that is not true of you. Ask the human before answering.
4. Read a refusal literally: "what they shipped" is a fact lookup, not a question about me. Search, then confirm with the human before changing an answer.
5. 'Certainty' hint: course pages and my own training can be stale. For 'latest X' questions, search the live web and cite the date.
6. Debrief rule of thumb: record the exact refusal text per snag; the refusal usually names its own fix ("line 06", "count again", "today's paper").
7. See docs/playbook.md for the checklist to run at the start of each challenge.
8. Creating a cloud routine attached all 11 claude.ai connectors by default (Gmail, Drive, Notion...) although none were requested. Always check mcp_connections in the create reply and clear them (clear_mcp_connections) for agents that read the web.
9. Test a claim on the real page before writing it down: I first said the schema was a plain link; the real page declares it in a <link rel=service-desc>, and the original script already found it.
10. Clean up test commits with path-limited commands. `git reset --hard` also discards uncommitted edits (it wiped my redact.mjs change once).
11. A sign-in link belongs to the browser that asked for it. A machine that did not ask gets 403; ask from the machine that needs the session.
12. Check the real constraint before you grant things: the HQ `proposers.allowed_tools` check allows three tools only, so the first token request failed. Read the migration first.
13. A first load can look done and still show an empty screen (Task screen with no steps). Open the consuming screen's data columns before calling it loaded.
14. Check which machine you are on (`hostname`, `ip`, running containers) before saying "this machine is not the server".
15. After a 429, stop. Each extra request can extend the block.
16. Model timestamps for speech were unreliable (the same sentence at 19.7 s, 64.9 s and 119.6 s depending on the model). Confirm offsets with `ffmpeg silencedetect`; take word content by majority across several runs.
17. A bot told "read-only, no shell" still ran shell commands when launched with `--yolo`. Do not rely on a prompt as a guardrail; do not give that worker untrusted input.
18. Read a secret out of another service only with the owner's explicit OK for that secret, hold it in memory, and never write it down.
19. PostgREST connects as a role with `pg_safeupdate` preloaded, so an `UPDATE` or `DELETE` without a `WHERE` fails there ('UPDATE requires a WHERE clause') but passes local pgTAP, which runs as `postgres`. Give single-row updates a real predicate, and keep the migration lint test (`shared/migrations-where.test.mjs` in mega-hq).
20. When two screens show the same number, put the rule in one helper. Today printed the stored step count while Task counted a solved challenge as fully done, so a solved S01E02 read 0 / 6 on one screen and 6 / 6 on the other (`web/src/lib/progress.ts`).
21. Check a deployment's claims against the running thing, not only the tests: a live read showed S01E01 with no notes after a 'done', and a served-bundle grep showed the web container still on the old build.
22. An OAuth loopback callback binds to the container's own `localhost`, not the human's browser's. When the agent's shell and the human's browser aren't on the same host, the only way to finish the flow is to hand the failed-redirect URL back and deliver it with `curl` from inside the container — plan for that hand-off, don't assume `--no-browser` paste-back alone gets you there.
23. A download gated behind a browser sign-in (no API) has to move through whatever channel the agent has, even a bad one: shipped S01E03's kb export as checksummed base64 chunks over an ~8000-char prompt limit, ~3 min per chunk. Fine once; a real system needs a proper file-transfer or signed-in-browser path.
24. "Logged in everywhere" doesn't mean every CLI is even installed. `gh` was missing entirely from the console's base image; check presence before assuming auth is the only gap.
25. (Corrected 2026-10-28 - the first version of this lesson was itself a wrong diagnosis, kept here so the mistake isn't silently erased.) Two tickets whose computed id-sets overlap are one problem filed twice, not two. S01E03 filed a 3rd ticket (#8, 5 ids) that was a plain subset of #6's own computed group (379 ids, #8's 5 included); the claim came back "two of yours are the same problem." The first guess at which two were duplicates was wrong too (blamed #6/#7 for similar-sounding fix text - rechecked later, their fix paragraphs are only 33% similar by string distance, nowhere near "the same"). Check id-set overlap on the computed groups before filing, not a hunch about prose similarity.
26. When renaming self-references in drafted GitHub issue text, check every bare `#N` against the target repo's *existing* issue numbers, not just the headline ticket you're trying to avoid autolinking — `#2` would have silently linked to an unrelated tracking issue already in the repo.
27. The kb's own code comments define what counts as a separate problem; the desk's reading (desk-notes.json) is a footnote, not a cause. S01E03's `readAs()` comment says exactly this ("counted where they're filed, footnoted under it") — the fix for lesson 25 trusted how the desk read 5 reports over what `causeOf()` computes, and split them into a problem that didn't exist.
28. When a fix for feedback gets proposed, check it against the source of truth before applying it — not just against the symptom that triggered the feedback. The first fix proposal (merge #6+#7) matched the surface complaint ("two of yours are the same problem") but contradicted `causes.ts`'s own comment calling them "a different bug." Re-reading the code, not re-reading the symptom, found the real duplicate (#8).
29. `claim-challenge` has a status beyond `solved`/`rejected`: `progress` — a step accepted, not solved, with its own required next action (here: "close your tickets, then send the repo again"). Don't assume a binary outcome; read `status` and act on exactly what `next`/`message` ask, not on an assumed pass/fail.
30. "What it shows": the rendered page is the product, not the tickets alone. S01E03's own incident page still said `status: known` and "one issue" after we'd filed two real tickets against it — a read-only sweep of GitHub and the challenge tools found no bot or timer waiting on us; the stale thing was our own kb page. When data and a page disagree, update the page, signed, don't wait for an external signal to tell you to.
31. A tool's own description can forbid the exact use a task suggests. `rook`'s description says "never on your own, and never to work on a Challenge" — a task that conditionally allowed calling it anyway didn't override that; the tool's stated boundary wins.
32. Closing tickets after a "not solved yet, close yours and resubmit" reply isn't automatically "the way the course expects" — S01E03's third claim came back rejected again ("closed, but not the way the desk would. Things moved since your first submit."), so the close+resubmit instruction wasn't the full picture. Don't treat a course hint as a complete recipe; treat it as one data point and stop to re-check after acting on it.
33. A downloaded export can be byte-identical and still stale, if the thing that changed is state, not data. S01E03's kb export re-downloaded with the same sha256 after the desk had already closed #4471 — the checksum proved the data was unchanged, not that nothing had moved; the live challenge page itself had an update the console (no browser) could never see on its own.
34. A browserless harness is blind to live page updates by construction, not by a fixable bug — this cost two full submit cycles on S01E03 before the coordinator's own browser caught it. When a challenge's state can change on a page, re-check that page (via whoever can see it) on every rejection, not just the first fetch.
35. A close reason carries meaning the course checks: "fixed" and "won't fix" are not the same as "closed." S01E03's tickets were correctly closed once (completed/completed) and still rejected until the reasons matched what engineering actually did (one fixed, one won't-fix) — `state_reason`, not just `state`, is part of the answer.
36. A source list is bigger than the file you opened. S02E01's archive listing held a zip plus three loose files for session c41e7b02; unzipping only the zip read nine sessions and missed the one that moved the image to 17 and the port to 5471. Diff the listing against what you read before you write the first plan.
37. "Something changed since your check-in" was literally true. Sessions kept arriving: c41e7b02 (image, port) was in the listing from the start and 5d8a1f37 (database `reorder_3hnq`, 14:45Z) appeared mid-run. The build passed once the first was in the plan and the claim was solved once the second was. After a second identical refusal, re-list the sources and diff; do not rotate plan variants.
38. A later decision overrides only what it names, and a helper's scope is not the owner's. The Oct 30 team changed SQLite to Postgres and left Drizzle standing; the CI subagent was asked to "fix the CI side" and wrote "same settings locally" on its own. Keep the rows it does not name, and take unrequested scope back to the owner before it enters the plan.
39. A hook in a project's own `.claude` settings file fires only for sessions started in that project. The S02E01 Stop hook lived in `found-out-late`, so a session opened in the home folder had none and `check-lane loop` said "not-looped". Put the hook where the session starts (`~/.claude/settings.json`) or start Challenges inside the project.
40. On a shared host, inspect read-only, name the write, ask, then run one action per call. A combined "read the password, push with --force, verify" command was refused by the permission check; the same steps passed one by one after the owner's yes. Keep the password out of any file you send to the course: the config reads `DATABASE_URL` and falls back to a URL with no password.
41. A running store's volume decides what you can change. A version-16 data folder will not start under `postgres:17`, and `POSTGRES_DB` only applies on first start. Look at what the volume holds and ask before you drop it; add a second database with `CREATE DATABASE` instead of recreating when you can.
42. The checker reads one row per fact. S02E01's plan was refused for "no image version" and then "no port" although both sat inside the Job store row. Give image, port and database name their own rows, each with its own session id and time.
43. Rehearse the round's shape before you spend a try. S02E02 round 1 was rejected `followup_forgot`: the agent passed 30 offline tests, but the course sends a link and then a follow-up in the same thread, and the agent answered each mail alone. A fake that copies your own assumptions cannot find that. Replay the likely sequence (follow-up, page gone, stranger in the thread, injection bait) through the real code and the real model with a simulated mailbox (`challenges/S02E02/agent/evals/rehearse.mjs`) and claim only when every run passes. The journal should log enough (subject, history size, reply preview) to diagnose a round without re-reading the mailbox.
44. What code can enforce, code should enforce, and the test must use the real mail text. A requested format ("ANSWER: <value>") is detected and enforced in code (send only that line); the first detector anchored the marker to the line start and missed Rook's real "one line again: ANSWER: <enqueuer>". A unit test with the real wording caught it before the next round. Also keep what the agent read (pages) per thread: a follow-up must not depend on fetching the page again.
45. Two sources can keep two clocks. S02E04's incident record said 22:50 US Eastern (summer time on 31 Oct, UTC-4) and the desk's notes were in central European winter time (UTC+1), so the same stall was the note at 03:50, not the one at 22:50. Convert on the right date before you join, and log the conversion.
46. A prompt for a remote worker is a deliverable. S02E04's first job 2 attempt failed because a wrong block was pasted into the cloud session; the worker answered it had no context. Put the prompt in its own file, name the job on the first line, say "paste alone", and say what a correct first reply looks like.
47. A remote place has its own network policy. S02E04's cloud session returned 403 on every request to the course host until the owner allowed that one host. Test reach with a read-only request before you spend a one-day job link.
48. A link is a key. Give it only to the worker that runs the job, and delete the helper files that hold it when the job is done (S02E04).
49. A step that waits on the other side is its own issue. S01E04's plan called the preview done once it was sent; the reviewer looked minutes later. Keep the marked copy untouched, check on a fixed interval, and change it only after they ask.
50. Uploaded is not reachable. S01E04's link was first fetched from a Mac on the tailnet, which proved nothing. Fetch it from outside, check status, certificate and the content you care about, then claim.
51. Read the repo's ADRs before you pick a host. S01E04's first idea, GitHub Pages in the same repo, was forbidden by an ADR because the marker would stay in git history; the NAS funnel kept it out.
52. When nothing comes back from a host, read the host's own log first. S01E05's first test ping failed because the service's PATH had no `claude`; the log said so (`spawn claude ENOENT`), the course had not refused anything.
53. A merged record loses its source labels. S01E02's second session guessed which recording was UTC, and the first claim was refused. Write the source of each part into the hand-off notes, and ask whoever kept the notes before you guess.
54. Check the MCP spec revision and the course's limits before you build a server. S02E03's first transcribe result was 1341 B (the transcript twice) and its error never named the url; both were refused. Return once, name the input, and say what to send instead.
55. Retyping a link or passphrase fails. S02E03's connect link was mistyped and expired, and the passphrase had look-alike letters. Copy by script or paste, note the expiry, avoid look-alikes, and rotate a passphrase that was printed in the session.
56. Take the enrolled address from the profile page. S01E04's sign-in mail arrived in 16 seconds once the dotted address form the profile shows was used; three runs with other forms failed.
57. A tag you saw is a tag you list. S03E01's first list had 14 of 15 tags because product typed a note in the recording and deleted it 10 seconds later; the course said `missing_tag: 1`. List retracted tags too and say they were retracted; the owner decides what counts.
58. Look in the course repo's `tools/` before you add a tool. S03E01 ran from the home folder, so `tools/transcribe` was not used and a new speech container on the NAS crashed once on a library version. Read the repo's `CLAUDE.md` and `tools/` first, whatever folder the session starts in.
59. A heard tag is a guess. S03E01's speech-to-text wrote R-M8Z as "RM8Z". Check each heard tag against the shape of the written ones (R-letter-digit-letter) and say which letters are unsure.
60. A page that draws its content has to be looked at. S03E01's live board was a canvas: its text and accessibility snapshot were empty. Take a screenshot and read that.
61. `claim-challenge` needs a `receipts` object on every call, even `{}` on the first one (S03E01). The receipt from step one goes inside `answer` for step two.
62. An ask to the owner must read as a question (S03E03). A comment that lists options and says "answer here with /answer n" was judged "no question to the owner". Open with a sentence that ends in "?", then the options one per line with their kind, then the recommendation.
63. In an unattended round the owner's answer is a thread entry, not a chat message (S03E03). When the round page loses the answer, do not stand in for it: retry from another browser and wait. Acting on the owner's chat instruction first ended the round (`built_before_answer`), even with the provenance written openly. Order of events is what the course checks.
64. Before the owner answers, the only ship line an issue may have is `asked` (S03E03). The course hint: "a ship line for the issue with any verb but `asked` is work on it". My loop wrote `waiting` at pick-up, so #2 failed `built_before_answer` in round 2 even with the right order of events. Acknowledge with a comment, not a ship line. Records, comments and labels are fine before the answer. Enforce it in the loop code, and rehearse with a raw capture of every ship line, not just the latest per issue.
65. A race only shows when the click is timed like a person's (S03E04). My first recording clicked a row three seconds after a new incident landed, on a page that held still, and the course refused it: "No incident landed near that ack." Aim the mouse at the row, wait for the real change, click at the old spot about 150 ms later, no stability wait, nothing mocked. The test-style click that waits for the page to settle cannot see the bug.
66. Read the moments from the video, not from your own clock (S03E04). My event log put the ack at 13.2 s; the frames showed "acked" at 12.2 s. Use `tools/video-sheet` and take the time from the red label on the frame.
67. Name evidence in the fields the course reads (S03E04). Claim 2 named both rows in the report text and was refused: "Name them in the evidence block as expected and got (incident ids)." Put `expected` and `got` in the block as fields, next to `at`, `receipt` and `sha`.
68. Ask what a replay does to live data before you approve it (S03E04). The course's replay sent three real acks on the owner's session, on top of my three. An ack cannot be undone. Read the pinned replay file or ask first, and tell the owner the total number of real acks before the claim.
