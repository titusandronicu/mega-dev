# Prep 2026-11-10: S03E02 "Translating Intent into Agent Work"

Sources read: the lesson text via mega-start, and the transcript of Kent's video (`~/Downloads/s03e02-transcript.md`, the Kody repo walkthrough).

## What the transcript teaches
- **Agents get it right first time because of the system, not a big prompt.** The system is a 20-line index file, a few principles, ADRs, and a list of every primitive.
- **AGENTS.md is only links.** CI fails if it passes 20 lines. Agents open only the pages that matter for the task, which saves context and attention.
- **ADRs hold decisions.** The template is status, date, context, decision with options and why, consequences, and a "revisit if" line. An ADR is not sacred. It is a record the next agent reads so it does not re-decide.
- **Principles are short pages.** Example: cleanup. When a new way replaces an old one, the migration is not done until the old one is gone. This stops "add a fallback just in case".
- **Primitives index.** A YAML file names every primitive (58 in 5 groups, 13 invariants). Each entry links its code and docs, so the agent composes existing pieces instead of inventing new ones. Merge near-duplicates under a common parent.
- **Verification is part of the system.** A control CLI and a skill let agents verify their own work, and agents file friction and improve the CLI themselves. The docs say verifying is expected.
- **PR template.** Intent, one-way or two-way door, cleanup, why, summary, issues, testing, and a system recap naming primitives added, changed or deleted. The reviewer reviews the system, not the code.

## Lesson text, in one line each
- **Intent:** give principles with reasons, not rules. A rule like "never delete files" becomes "match your caution to the cost of being wrong".
- **Context:** product knowledge that code can't show. Kent uses ADRs. Lauren Tan uses durable principles, skills and types. Both aim at fewer questions and better decisions.
- **Agreement:** scope, outcome, boundaries and proof. Make it visible with visuals, comparisons, graphs or a lab.
- **Evaluation:** define success and failure, use deterministic checks where possible, and build the tools the agent needs to prove its work.
